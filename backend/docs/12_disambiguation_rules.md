# Author and Institution Disambiguation Rules

Implemented in `backend/src/disambiguation/`, run by
`python -m src.pipeline.build_disambiguated_entities`.

This document is the specification. Where the code and this document disagree,
the code is wrong.

## 1. Scope

Disambiguation answers "which real-world entity does this mention refer to?".
It is a different problem from deduplication (`src/deduplication`), which asks
"are these two records the same publication?".

Two entity types are resolved:

| Entity | Input | Output |
| --- | --- | --- |
| Author | Each name in `authors`, per record | A cluster ID plus a confidence label |
| Institution | Each string in `institutions` / `sri_lankan_institutions` | A registry institution ID plus a method and confidence |

Nothing here modifies the publication dataset. Resolution is an **overlay**:
outputs are written beside the corpus, keyed back to it by `record_key`, so a
consumer chooses how much of it to trust. Disambiguation is uncertain, and
uncertainty that has been written into the primary dataset cannot be undone.

## 2. What the data actually supports

Three properties of this corpus set the ceiling on what any rule can claim.
They were measured, not assumed.

**ORCID coverage is low and mostly unattributable.** 21,659 records (12.7%)
carry any ORCID. Of those, the ORCID can be tied to a *specific* author on
about 10% — see §4.1. ORCID therefore resolves a small minority of the corpus,
and the rest rests on weaker evidence. Any claim that this pipeline
"disambiguates by ORCID" would be true of a rounding error.

**Affiliation is absent from 57% of records.** `institutions` and
`sri_lankan_institutions` come from OpenAlex exclusively. Records sourced only
from repositories or SLJOL have no affiliation at all, so the affiliation rule
simply does not fire for them.

**The `authors` field contains name fragments.** Many records list partial
names beside their own full form — one row carries `Gyan Prasad Bajgai`,
`Sangay Tshering`, `Gyan Prasad`, `Birendra` and `Sangay Bajgai` for a
five-author paper. This is an upstream artefact. Left in place, every fragment
becomes a phantom author, so they are removed before clustering (§3.3).

## 3. Author disambiguation

### 3.1 Name parsing

All comparison happens on parsed names, never raw strings.

- Unicode is NFKD-normalized and diacritics folded, so `Pereră` and `Perera`
  agree.
- `Surname, Given` is detected by a single comma splitting the string into two
  non-empty halves, and reordered.
- Initial runs are expanded: `T.K.K.` becomes three initials, not one token.
- Honorifics (`Prof`, `Dr`, `Ven`, …) and suffixes (`Jr`, `PhD`, …) are dropped;
  they carry no identity and collide across people. **An all-uppercase token is
  never treated as one**, because the honorific list overlaps the initial space:
  `MS Perera` is M.S. Perera and `Perera, JNR` is Perera, J.N.R. Stripping those
  leaves a bare surname, and before this guard existed it collapsed 1,575
  publications into a single false "Perera" identity. The residual error is an
  all-caps name like `DR W PERERA`, where `DR` is read as initials — that
  over-splits by one identity, which is the safe direction.
- Surname particles stay attached: `de Silva` and `van der Berg` are one
  surname. Splitting them would turn a common Sri Lankan surname into a given
  name.

The parsed identity key keeps given names and initials **separate**.
`Wimal Perera` and `W. Perera` are different keys. Collapsing them would merge
two mentions with no evidence at all, which is precisely the failure this
module exists to prevent.

### 3.2 Blocking

Candidate pairs are generated by `surname + first given initial`. Only
within-block pairs are ever compared.

The block is deliberately loose. `Wimal Perera` and `W. Perera` must land
together, because the scoring stage can reject a bad pair but can never recover
one that was never compared. Surname-only mentions get their own block so they
are never silently absorbed into a named person.

Blocks larger than `MAX_VARIANTS_PER_BLOCK` (60 variants) are **not** scored
pairwise. These are very common surname-initial combinations where name
evidence is worthless anyway; they receive ORCID and exact-name merging only,
and are flagged `oversized_block` for review. Producing a plausible-looking
clustering there would be inventing precision the data does not contain.

### 3.3 Fragment removal

A mention is a fragment when its full-word tokens are a strict subset of
another mention's tokens **on the same record**. Fragments are dropped before
clustering.

Single-token and initials-only mentions are never treated as fragments.
`W. Perera` beside `Wimal Perera` is far more likely the same person written
twice than a subset artefact, and deleting it would lose a real mention. The
clustering stage merges those on evidence instead.

### 3.4 Evidence and scoring

Weights sum to 1.0, so a score reads as a fraction of the available evidence.

| Evidence | Weight | Rationale |
| --- | --- | --- |
| Name compatibility | 0.45 | Necessary, never sufficient |
| Shared coauthor | 0.30 | Strongest non-identifier signal: research groups are small relative to the name space |
| Shared institution | 0.15 | Weak alone — large universities host many people sharing a surname and initial |
| Shared field | 0.10 | Weakest; a tie-breaker |
| Shared record-level ORCID | 0.05 | Corroboration only, see §4.1 |

Thresholds:

| Score | Outcome |
| --- | --- |
| ≥ 0.85 | Merge, `high` confidence |
| ≥ 0.70 | Merge, `medium` confidence |
| 0.45 – 0.70 | **No merge.** Sent to the author review queue |
| < 0.45 | Distinct |

Two rules override scoring entirely, in both directions:

- A shared **attributed** ORCID merges, regardless of everything else, and
  across block boundaries. This is the only rule that can join `Deepagoda,
  T.K.K.C.` to `Thuduwe Chamindu Deepagoda`.
- **Different** attributed ORCIDs reject, regardless of everything else. Two
  variants with distinct ORCIDs are two people no matter how similar their
  names or how many coauthors they share, and soft evidence must never outvote
  that.

Merging is deliberately conservative. An unmerged pair costs a split identity,
which is visible in the output and fixable by review. A wrong merge fuses two
researchers' publication records into one, which is neither.

### 3.5 Cluster confidence

A cluster's confidence is set by the **weakest** merge that built it — a chain
is only as trustworthy as its loosest link.

| Label | Meaning |
| --- | --- |
| `orcid_confirmed` | At least one attributed ORCID |
| `high` | Every internal merge scored ≥ 0.85 |
| `medium` | Some internal merge scored 0.70–0.85 |
| `name_only` | A single name variant that never merged with anything |

`name_only` is not a quality claim. It means the rules found no evidence either
way, which is the normal state for most of this corpus.

## 4. Use of specific evidence types

### 4.1 ORCID

**Positional attribution is refused by default.** `author_orcids` is built by
`unique_join`, which deduplicates and drops empty values. An ORCID at index *i*
is therefore not the ORCID of author *i*: for a record listing 13 authors and
one ORCID, position tells you nothing.

Attribution is permitted only when all three conditions hold:

1. at least one contributing source is order-preserving (OpenAlex or Crossref);
2. the author count and ORCID count are exactly equal;
3. no author name repeats on the record.

Condition 2 does most of the work. Because `unique_join` only ever *shortens*
the list, an ORCID count still equal to the author count means nothing was
dropped, so the positions are intact.

Note that `source_dataset` on a merged record is a semicolon-joined list
(`"openalex; crossref"`), not a single value — condition 1 is an intersection
test, not string equality.

Where attribution is refused, the record's ORCIDs remain **record-level**
evidence. They can say "these two mentions appear on records carrying the same
identifier", which contributes 0.05, but they cannot say "this author is that
ORCID", and they never trigger the override rules in §3.4.

### 4.2 Affiliation

Affiliation strings are resolved to registry institution IDs first (§5), and
the resolved IDs are compared. Comparing raw strings would miss
`University of Moratuwa` against `Dept. of Civil Engineering, Univ. of
Moratuwa`.

Both `sri_lankan_institutions` and `institutions` feed the signal. The former
is far cleaner (3,445 vs 26,211 distinct values) but is the domestic subset
only, so restricting to it would discard every foreign affiliation.

### 4.3 Coauthors

A mention's coauthors are the blocking keys of the other authors on the same
record. Blocking keys rather than full names, so `Nimal de Silva` and
`N. de Silva` count as the same coauthor.

This is the highest-weighted non-identifier evidence, because two researchers
who share a surname and initial rarely share a collaborator.

## 5. Institution disambiguation

Affiliation strings are addresses, not names: unit, parent, city, country,
sometimes a postcode, in no fixed order. Resolution means finding the
institution inside the address.

Rules run in strict precedence, and each result records which rule fired:

| # | Method | Confidence | Rule |
| --- | --- | --- | --- |
| 1 | `ror` | `certain` | An explicit ROR identifier in the string |
| 2 | `registry_exact` | `high` | The whole string is a known name or alias |
| 3 | `registry_segment` | `high` | A comma-separated segment is. Longest segment first, so `University of Moratuwa` beats a bare city name |
| 4 | `registry_fuzzy` | `medium` | Token overlap (Jaccard) with a registry entry ≥ 0.62 |
| 5 | `unresolved` | `none` | Nothing matched. Reported, never silently dropped |

Fuzzy matching compares **content tokens only**. Generic tokens (`university`,
`institute`, `faculty`, `department`, `sri`, `lanka`, `univ`, …) are removed
first, because left in they make every pair of universities look similar — the
discriminating token is the place name. `University of Colombo` against
`University of Kelaniya` scores 0.0 rather than 0.33.

The registry is
`research_analytics.institutions.NationalInstitutionRegistry`, loaded from
`configurations/<country>/institutions.csv`. These rules add layers on top; they
do not fork it. **An institution absent from the registry stays unresolved** —
the rules will not invent scope decisions. Whether `Department of Archaeology`
(3,690 records) counts as an in-scope research institution is a registry
question, and answering it means editing that CSV.

## 6. Review queues

Rules cannot finish this job. What they can do is refuse to guess and hand a
human the cases where evidence ran out, ranked so scarce review effort lands
where it matters.

### 6.1 Authors — `review_authors.csv`

Only **flagged** clusters appear. An unflagged cluster is not "reviewed and
accepted"; it is one where the rules found enough evidence, and re-checking all
of those by hand would be equivalent to having no rules.

Flags and the action each implies:

| Flag | Action |
| --- | --- |
| `multiple_orcids` | Split the cluster, or confirm duplicate ORCID registrations |
| `oversized_block` | Name is too common to score; confirm via affiliation and coauthors or accept it stays unresolved |
| `near_threshold_pair` | Confirm or reject the pair listed in `near_miss_pairs` |
| `orcid_conflict_nearby` | Check this is not the unidentified half of an ORCID-conflicting pair |
| `name_only_multi_record` | Several records merged on name alone; verify before reporting as one researcher |
| `surname_only` | Recover the given name from the source record |

Ranking is `publication_count × confidence_weight × (1 + 0.25 × flag_count)`.
A name-only cluster of 60 publications outranks the same uncertainty on one
record, and an ORCID-confirmed cluster with a stray flag ranks low because the
identifier already settles the identity.

### 6.2 Institutions — `review_institutions.csv`

Both unresolved strings and fuzzy matches are queued. A fuzzy match is a guess
the registry should be *taught* — by adding the alias — not a result to leave
at medium confidence forever. Ranking is by affected record count, with fuzzy
matches at half weight since they are already usable.

Each row states the closest registry candidate and its score, so a reviewer can
decide between "add an alias", "add a new institution" and "out of scope"
without going back to the raw data.

## 7. Outputs

Written to `data/processed/common/disambiguation/`:

| File | Contents |
| --- | --- |
| `author_clusters.csv` | One row per resolved author identity |
| `author_cluster_members.csv` | Mention → cluster, joinable to the corpus on `record_key` |
| `institution_resolutions.csv` | Affiliation string → institution, with method and score |
| `review_authors.csv` | Ranked ambiguous author clusters |
| `review_institutions.csv` | Ranked unresolved affiliations |
| `disambiguation_summary.csv` | Run metrics, for tracking coverage over time |

## 8. Known limits

- Author resolution is **name-and-context based** for the overwhelming majority
  of the corpus. It is not identity resolution and must not be reported as
  such. `disambiguation_level` in the API remains `name` for any cluster below
  `orcid_confirmed`.
- Coauthor evidence is weak for single-author publications, which have none.
- Records without affiliation (57%) lose the institution signal entirely.
- Fuzzy institution matching cannot distinguish an institution from its own
  parent when the registry lacks the child.
- The rules do not detect a researcher who changed name, nor split a single
  ORCID shared by two registrations.
- No rule here reduces the corpus's underlying missingness. Disambiguation
  makes what is present more usable; it does not add evidence.
