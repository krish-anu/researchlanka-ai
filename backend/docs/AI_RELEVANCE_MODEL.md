## Artifact

The manifest resolves the artifact relative to `backend/`:

```text
data/models/ai_relevance/metadata_ablation_precision_092/A2_title_abstract_keywords.joblib
```

Expected SHA-256:

```text
f315d362c61a47b04c3e5bbad3a1054b75550bffcdd92825ecb7ce609903773d
```

The binary artifact is intentionally ignored by Git. Transfer it through the
approved model-artifact channel after its public license has been selected, and
verify the checksum before use:

```bash
cd backend
sha256sum data/models/ai_relevance/metadata_ablation_precision_092/A2_title_abstract_keywords.joblib
```

## Dataset compatibility

The checked-in `researchlanka-ai-dataset/` package was generated by the legacy
linear SVM and is not output from this A2 model. It remains a release candidate
until it is regenerated, corrected, re-audited, and approved for redistribution.
See the root `HANDOVER.md` and the dataset `QUALITY_REPORT.md` for blockers.

## Changing the production model

1. Evaluate the candidate on an appropriate held-out, human-reviewed set.
2. Record its feature contract, thresholds, training dataset, and metrics.
3. Save the artifact outside Git and calculate its SHA-256.
4. Update the manifest in the same reviewed change as the inference behavior.
5. Regenerate and audit downstream datasets before publishing them.
6. Update this page and `HANDOVER.md`.

Superseded A1 reports and experimental runbooks are retained under
[`archive/model-history/`](archive/model-history/README.md).
